## What the exclusion of the e-bike corpus changed

Books dropped: `Ai_generated_ebike_motor` (238), `Bafang` (178), `error_code_guide` (107), `Controller_Reference` (68), `Ninebot` (16), `xiaomi_ebike_escooter` (7) — 614 chunks, all electric.

Consequence: the **bottom-bracket standards table** (BSA 68/73, BB86 86.5/41, BB92 89.5/41, PF30 68/46, T47 68–86.5/47) existed only in the e-bike manual. The two bicycle manuals state that shell type and dimensions must match, but they do not tabulate the standards. So `BB-STANDARD` is now manual-backed only at the level of "must match the shell", not "here are the standards". That is recorded in `open_questions`.

## How the numbers are produced

- **Coverage** — counted from the catalogue: how many rows in that category carry each attribute.
- **Manual support** — FTS hits per category, restricted to the two bicycle books, with the top pages kept.
- **Quote verification** — every `basis: "manual"` rule has a quote that was checked as a verbatim substring of that book/page in `kb.db`. The builder counts `manual` only when that check passes; otherwise the rule is marked `manual-quote-unverified` and `needs_manual_check: true`.

Current result: **18 manual-backed, 37 mechanical-inference**. The 37 are the review's real work — they are plausible mechanics with no page behind them yet.

## Vocabulary

`must_have` → mismatch **excludes**, missing → `cannot_confirm`.
`nice_to_have` → mismatch ranks down, missing is ignored.
Outcomes: `fits` · `fits_with_caveat` · `cannot_confirm` · `excluded`.
